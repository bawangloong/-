# 评测口径

`evaluate.py` 按清单调用 `pipeline.py`，对照标注计算定位、颜色、字符数、逐字识别、整牌识别和运行时间。检测、校正、颜色、分割和字符识别都不在这里实现。

合成夹具只检查这套算术。夹具打印出来的分数不是系统实测，不能写进测试表、报告或幻灯片。

## 怎么运行

在仓库根目录：

```bash
python eval/evaluate.py --fixture
python eval/evaluate.py
python eval/evaluate.py --manifest data/splits/manifest.json --splits validation,final_test --iou 0.5
```

`--fixture` 不寻找流水线。它读取 `eval/fixtures/cases.json`，对照其中手算的计数；一致时打印「夹具对照：通过」。

不加 `--fixture` 时，脚本到仓库根目录找 `pipeline.py`，也可以用 `--pipeline` 指定路径。文件不存在就退出码 2，并打印以 `pipeline missing:` 开头的说明。文件在但导入失败，或没有 `run`，退出码 3，那不是 missing。

默认清单是 `data/splits/manifest.json`，默认只评 `validation` 和 `final_test`。这两个名单现在是空的：一旦流水线文件存在，脚本会说明没有图像、没有调用流水线、没有评测结果。名单为空时流水线文件还不存在，则先报 `pipeline missing`。

标注或图像文件没准备好时，脚本停止，不输出指标。流水线对某一张图抛错时，该图只计入 `n_errors`，不进入各项准确率的分母。

## 流水线要返回什么

`pipeline.py` 提供：

```python
def run(image_path: str) -> dict:
    return {
        "plates": [
            {
                "box": {"x": 0, "y": 0, "w": 0, "h": 0},
                "number": "",
                "color": "unknown",
                "char_count": 0,
                "chars": [],
            }
        ]
    }
```

也可以直接返回 `plates` 列表。没有车牌时返回 `{"plates": []}`。

`box` 是原图像素坐标，不是校正后小图里的坐标。一张图可以有多块牌，顺序无所谓，配对按框而不是按下标。

`color` 用颜色闭集或别名。看不清必须显式给 `unknown` 或「未知」。不写这个字段不算未知。

`char_count` 是分割得到的字符数。写了就按这个数评分，脚本不会用号码长度把它改掉。

`chars` 是从左到右的字符。有这个字段就用它算逐字准确率；没有就拆 `number`。整牌字符串优先用 `number`。`char_scores` 和 `score` 可以带上，当前指标不用阈值卡它们。

## 定位

坐标系与标注相同：原图左上角为原点，框是 `{x, y, w, h}`。

交并比 IoU = 交集面积 / 并集面积。边只贴在一起、重叠面积为 0 时，IoU 为 0。

默认命中阈值是 **IoU >= 0.5**。`--iou` 可以改，报告里写出实际用的阈值。

配对只在同一张图内做。先留下达到阈值的（标注框，预测框），按 IoU 从高到低贪心，每个框最多用一次。IoU 相同时，标注下标小的优先，再比预测下标。

- TP：配上的框对。
- FP：没配上的预测框。
- FN：没配上的标注框。
- 精确率 = TP / (TP + FP)。
- 召回率 = TP / (TP + FN)。

分母为 0 时，该率写成空值，不写成 1。没有车牌的图没有框，不进这两个率。

车牌是否存在：标注 `has_plate` 与「预测 `plates` 非空」是否一致。这是图像级准确率。

## 颜色

闭集：`blue`、`yellow`、`green`、`white`、`black`、`unknown`。

别名：蓝 / 蓝色 / 蓝牌，黄 / 黄色 / 黄牌，绿 / 绿色 / 绿牌 / 新能源 / 新能源绿，白 / 白色 / 白牌，黑 / 黑色 / 黑牌，未知 / 无法判断。比较在归一化之后做，必须完全相等。

只统计已经配上的车牌。缺字段、空字符串和闭集以外的词都算错，并且不等于 `unknown`。

颜色准确率 = 配上且颜色相等的数量 / 配上的车牌数。

## 字符数量

只统计已经配上、并且标注写了 `char_count` 的车牌。两边的整数必须相等。

预测优先用返回的 `char_count`；没有该字段时，用下面的字符序列长度。

字符数量准确率 = 相等的配对数 / 参与的配对数。

## 字符识别

字符序列：预测或标注有 `chars` 就用 `chars`，否则把号码拆开。去掉空白和间隔符 `· • ・ . - — _ / ． 。`，拉丁字母转成大写，汉字不变。

从左到右按下标比。下标 `i` 算对，当且仅当预测序列比 `i` 长，且两边字符相同。预测多出来的字符不进分母。

- 定位命中后：分母是配上的、号码归一化后非空的车牌的标注字符总数。这是字符识别的主数字。
- 端到端：分母再加没配上的、有号码的车牌的全部字符，这些字符都算错。

号码为空的标注不参与这两项。

## 整牌识别

整牌字符串取 `number` 做同样的归一化。没有 `number` 时才把 `chars` 拼起来。必须整串完全相等。

- 定位命中后：配上的、有号码的车牌里，整串相等的比例。
- 端到端：全部有号码的标注车牌里，既配上且整串相等的比例。没配上算错。

全牌识别率以端到端这个数为准，同时报告命中后的比例，这样定位失败不会被算进字符模块。

## 运行时间

用 `time.perf_counter()` 包住每一次 `pipeline.run(image_path)`。起点在调用前，终点在返回后。

计入流水线内部的读图、检测、校正、颜色、分割和识别。不计入读清单、读标注、算指标和写报告。没有预热，每张选中的图像测一次。

报告给出张数、总和、算术平均、中位数，以及最近秩 p95。p95 的下标是 `ceil(0.95 × n) - 1`。调用失败的图像不进时间统计。

夹具也会带上计时字段。那是空预测数据的耗时，不是系统运行时间。

## 合成夹具在检查什么

`eval/fixtures/cases.json` 有 8 张虚构图，没有真实照片：无牌正确、无牌误报、完全正确（号码带间隔符）、IoU 刚好 0.5、一图两牌加一个多余框、IoU 0.25、显式未知颜色、缺少颜色字段。对照计数写在同一个文件的 `expected` 里。

这些计数是指标实现的对照答案。系统还没接入，所以它们不是识别率。
