# 五分钟讲解稿

这是口播稿，不是已经录好的视频。本仓库没有视频文件，也没有在镜头前重开 GUI。口播按每分钟大约 220 个字估算，正文约 900 字，连同停顿在 5 分钟以内。方括号里的字不要念出来。

演示若以后补拍，只用 `data/raw/development/` 里的图。正式数字仍来自已经冻结的 validation 和 final_test，不要把终测图片抽去演示。

## 口播

【0:00–0:25】

各位老师、同学。我们做的是车牌识别。A 负责检测和矫正，B 负责颜色和字符分割，C 负责字符库匹配，D 负责把它们串成界面和一次调用。E 负责数据划分、评测，以及现在这份报告和幻灯片。

【0:25–1:15】

一张图的顺序是固定的。先在原图上找车牌，给出框。再把车牌矫正成正向小图。然后判断蓝、黄、绿、白、黑。接着把字符从左到右切开，每字做成白笔画、黑背景的小图。最后和字符库里的样本比相似度，拼出号码。没有车牌时，结果列表为空。

【1:15–2:05】

这次写进课程表的，只有一次已经跑完的评测。名单是冻结的 validation 和 final_test，共 17 张图、19 块标注牌。用的是提交仓库的 `pipeline.run`。那个克隆里没有 `vendor/a_plate`，所以检测是仓库自带的传统检测，框上的来源是颜色或梯度，不是 `received/a` 里的检测脚本。八张合成样本和指标夹具没有算进来。号码为空的三块牌不参与逐字和整牌。

【2:05–3:15】

存在判断是 9/17。定位精确率是 5/22，召回率是 5/19，也就是命中 5、误检 17、漏检 14，IoU 阈值 0.5。配上的五块牌颜色是 5/5，字符数量是 1/5。逐字在定位命中后是 4/35，端到端是 4/115。整牌在定位命中后是 0/5，端到端是 0/16。17 张图都返回了，平均大约 0.17 秒。五块里唯一字数对上的是终测那块「西城0414」，预测成「晋冀0414」，后四位相同，前两个汉字不同。

【3:15–4:20】

【若补拍，这里打开程序，不要念括号。】先打开 development 里一张没有可标车牌的图，结果应是空列表。再打开一张有多块牌的图，列表里应能逐块切换。最后选一个文本文件，界面应按 D 的错误码提示类型不受支持。这三段这次没有拍摄。D 的记录里，第二台没有安装 Python 的电脑尚未填写复测表，所以不说 exe 已经在另一台 Windows 电脑上测过。仓库里的 exe 只是一个很小的启动器，完整运行时没有放进 Git。

【4:20–4:45】

材料里现在有报告、幻灯片和这份讲稿。完整的小组压缩包还缺视频文件，以及可以单独运行的 Windows 运行时。课程数字以 `eval/results/system-evaluation.json` 为准。
