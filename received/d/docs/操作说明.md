# 车牌识别系统 · 操作说明

## 一、运行

### 方式 1：免安装 exe（推荐）

1. 解压整个压缩包（不要只把 exe 拖出来，`runtime/`、`vendor/` 必须和 exe 同级）；
2. 双击 `车牌识别系统.exe`；
3. 首次启动约 1~3 秒（加载 9517 个字符样本），之后即可选图。

目标电脑不需要安装 Python、OpenCV 或其他库，也不需要联网。

### 方式 2：源码

```bash
pip install -r requirements.txt
python main.py
```

## 二、界面操作

窗口分三块：

1. **左侧**：原图显示区，识别后车牌用绿色四边形框出并标注序号和号码；
2. **左下**：车牌列表，一张图有多块车牌时点击切换；
3. **右侧**三个标签页：
   - **识别结果**：号码、颜色、字符数、平均匹配分、本块耗时、每个字符的切片和匹配分；
   - **处理过程**：车牌裁剪 → 二值化 → 字符框 → 逐个字符切片；
   - **运行日志**：每次操作的记录，出错时也写在这里。

### 按钮

| 按钮 | 快捷键 | 说明 |
|---|---|---|
| 选择图片 | Ctrl+O | 打开本地图片，支持 JPG/PNG/BMP/TIF/WEBP |
| 开始识别 | F5 | 后台识别，期间可点“取消” |
| 取消 | — | 请求终止当前识别，界面不会卡死 |
| 保存结果 | Ctrl+S | 选择文件夹，导出标框图、过程图、字符图和 JSON |
| 打开结果目录 | — | 打开上次保存的目录 |

## 三、保存的内容

每次保存在所选目录下新建 `<图片名>_<时间>_结果/`：

```
01_原图标框.png          原图 + 所有车牌框
车牌1_裁剪.png           矫正后的车牌
车牌1_过程.png           四联过程图（报告/视频可直接用）
车牌1_字符/01.png …      每个字符放大 3 倍
02_结果摘要.txt          号码、颜色、字符数、警告
03_结果.json             完整结构化结果（可给 E 做评估）
```

## 四、异常情况会怎样

| 情况 | 界面表现 |
|---|---|
| 取消选图 | 静默返回，日志记录“已取消选择图片” |
| 选了 .txt 等非图片 | 弹窗“文件类型不支持”，不进入识别 |
| 图片损坏 / 伪扩展名 | 弹窗“图片无法解码或已损坏” |
| 中文路径 / 中文文件名 | 正常打开和保存 |
| 未检测到车牌 | 弹窗提示，结果区保持不变 |
| 字符数不是 7/8 | 仍尝试识别，结果区标注“字符数异常”，提示仅供复核 |
| 某个字符匹配分低 | 该字符分数标红，提示“建议人工复核” |
| 识别中关闭窗口 | 二次确认后退出 |
| 程序未预期异常 | 弹窗 + 写入 `logs/plate_app.log` |

## 五、提高识别成功率的建议

1. 车牌尽量占画面 1/10 以上，避免过小；
2. 避免强反光正对车牌、夜间噪点过大的图片；
3. 倾斜角度建议小于 30°，程序会做透视矫正；
4. 一张图有多块车牌时，尽量都完整出现在画面内；
5. 新能源 8 位车牌已支持，字符数会显示 8。

## 七、常见问题

**Q：双击 exe 没反应？**
查看同目录 `logs/startup_error.log`；多数是压缩包没有完整解压，`runtime/` 丢了。

**Q：提示“字符库文件缺失”？**
`vendor/c_char/character_library/library.npz` 必须存在，重新解压完整包。

**Q：为什么识别成“蒙A88888”而不是“京A88888”？**
字符库中“京/蒙”字形相近时会混淆，属于 C 模块的识别误差，可在报告中作为
混淆字符案例记录。

**Q：绿色包和 PyInstaller 版有什么区别？**
功能相同。绿色包用自带 Python 运行时 + 启动器，离线可用；PyInstaller 版
按 `docs/环境与打包说明.md` 用 `build/plate_app.spec` 生成单目录发行包。
