# A 模块报告初稿：车牌检测、定位与矫正

> 车牌识别系统大作业 · A 同学负责部分
> 本稿供 E 整合进大作业报告，含方法、实现、结果、问题与改进。

## 1. 任务与边界

A 模块负责把整张图片中的车牌找出来，输出可供后续处理的车牌图片，具体包括：
判断有无车牌、处理一张图中的多块车牌、筛选候选区域、对倾斜车牌矫正与裁剪。

模块边界：到「输出摆正的车牌裁剪图」为止。颜色类别最终判定、字符分割、字符识别、
GUI 与打包分别属于 B/C/D。A 提供底色线索 `color_hint` 供参考，但不替代 B 的颜色识别。

技术路线采用 **Python + OpenCV 传统方法**（颜色 + 边缘 + 形态学），可解释、离线可运行，
覆盖蓝/黄/绿/白底车牌与常见 7 位、8 位车牌，不依赖神经网络与训练。

## 2. 检测方法

### 2.1 总体流程

输入原图 → 预处理 → 双通道候选 → 几何筛选 → 收紧与字符验证 → 评分 → NMS 去重 → 输出定位结果。

### 2.2 候选区域提取（双通道）

- **颜色通道**：转 HSV，对蓝/黄/绿/白分别阈值化得底色掩码，小核形态学闭运算连成块，
  取轮廓最小外接旋转矩形作为候选。颜色通道直接给出牌面边界，定位较完整。
- **边缘通道**：灰度图经双边滤波去噪，Sobel 提取竖直边缘，Otsu 二值化后横向闭运算，
  利用「车牌字符区竖直边缘密集」的特征连成块。边缘通道对底色不敏感，可补充白牌等。

### 2.3 候选筛选依据

1. **几何**：长宽比 1.9~6.0（标准牌 440/140≈3.14，新能源 480/140≈3.43），
   最小宽 60px / 高 16px，倾角 ≤45°。
2. **收紧**：用底色掩码把粗框收紧到真实牌面；当掩码填充率 <0.82（车牌与同色背景粘连）时，
   用字符边缘的活动范围反推整牌——字符带约占领牌宽 95%，牌高按标准长宽比反推，
   避免边缘通道只覆盖字符区而切掉首字。
3. **字符验证**：
   - 字符峰数 6~16：水平投影找峰，排除纯色块与字符碎片；
   - 字符带高度占比 0.45~0.92 并排除边框行：排除广告牌大字与整块广告牌。
4. **评分**：颜色覆盖率、字符纹理、长宽比接近度、边缘密度加权求和，阈值 0.42。
   底色线索用候选框**外环**颜色判定，避免白色字符被误判为白牌。
5. **NMS**：IoU>0.3 或包含关系去重；重叠时优先保留颜色通道整牌框。

## 3. 矫正原理

1. 检测 quad 外扩 3% 防切字，透视变换摆正到标准朝向，宽度归一到 160~480px。
2. 用字符连通域的最小外接矩形拟合残余倾角，做小角度旋转微调（0.6°~15°）。
3. 按底色一致性裁掉四周外框/铆钉边条（每侧最多 15%，裁太多则放弃以防误裁字符）。
4. 三步变换复合为 3×3 单应矩阵 `transform`，保留矫正图与原图的坐标对应关系，
   后续模块可用其逆矩阵把字符位置映射回原图。

## 4. 实现与接口

- `plate_common.py`：全组公共契约。定义 `PlateRegion`（bbox/quad/angle/score/color_hint）、
  `RectifiedPlate`（region/image/transform），统一坐标约定（一律对应原图）、图像格式（BGR uint8）、
  错误约定（无车牌返回空列表，异常输入抛 `PlateIOError`），并提供中文路径安全的读图/写图。
- `detect_plate.py`：`detect_plates(image) -> list[PlateRegion]`，按得分降序。
- `rectify_plate.py`：`rectify_plates(image, regions) -> list[RectifiedPlate]`。
- `run_demo.py`：独立运行示例，保存标框图、逐牌裁剪图与 result.json。

## 5. 实验结果

### 5.1 测试集

合成测试集 14 张（`make_test_images.py` 生成，带真值标注），覆盖：正常蓝牌、+12°/-9° 倾斜、
黄牌、新能源绿牌(8位)、白色警牌、多车牌(3块)、小车牌、模糊、低光照、干扰广告牌、
无车牌(2种)、大倾角30°。异常输入另测错误类型、伪装扩展名、损坏图片、不存在文件、超小图。

### 5.2 合成集指标（IoU≥0.5 记为命中）

| 指标 | 数值 |
|---|---|
| 真值车牌总数 | 14 |
| 检出率 recall | 100% |
| 精确率 precision | 93.3% |
| 命中平均 IoU | 0.953 |
| 单图平均检测耗时 | 约 40 ms（CPU） |

无车牌图正确返回空列表；异常输入全部正确拦截并给出中文提示。
唯一误检为干扰图中形似车牌的蓝底白字广告牌文字行（传统方法硬案例）。
逐图结果与可视化见 `docs/定位效果记录.md` 与 `results/batch/`。

### 5.3 真实照片集结果

用 28 张真实车牌照片验证（文件名即车牌号真值，分绿牌/正常蓝牌/倾斜牌/黄牌四组各 7 张）：

| 指标 | 数值 |
|---|---|
| 单牌正确检出 | **26 / 28** |
| 漏检 | 2 |
| 多检 | 0 |

漏检的 2 张（皖A037G9、皖AX910B）为小幅面(~140px)+透视畸变+低对比度+周围车身纹理干扰，
颜色掩码碎片化，属传统方法能力边界。其余 26 张均正确检出单块车牌并输出摆正裁剪图，
绝大多数裁剪字符完整（个别与草丛粘连的绿牌末位字符略切）。
逐图结果与对照图见 `docs/真实数据集测试记录.md` 与 `results/real/对照图.png`。

## 6. 问题与改进

### 6.1 开发期发现并已修复的问题

合成集阶段：
1. **字符碎片误检**：蓝牌上的白色字符曾被当成白牌 → 外环底色判定 + 字符峰数过滤。
2. **背景色块粘连**：车牌与同色背景块相连导致框偏大 → 底色掩码收紧 + 边缘活动范围反推整牌。
3. **广告牌误检**：蓝底白字广告牌形似车牌 → 字符带高度/留白验证排除。
4. **边缘框切字**：边缘通道只覆盖字符区，NMS 保留它会切掉首字 → 重叠时优先保留颜色通道整牌框。
5. **倾斜裁剪方向错误**：大倾角时角点顺序导致裁剪旋转 90° → 统一长边为阅读方向。

真实数据集阶段（针对真实照片进一步加固）：
6. **有色背景误检**（蓝车身/绿草丛/白保险杠）：引入**连通域字符数验证**（真实牌 6~10，背景 ≤2）
   + 底色覆盖率门槛 + 白牌黑色字符结构检查，多检从大量降至 0。
7. **褪色蓝牌漏检**：真实蓝牌阴影下饱和度可低至 S≈40 → 放宽蓝色 HSV 范围。
8. **透视畸变长宽比偏低**：侧拍车牌表观长宽比降至 1.7~2.0 → 放宽长宽比下限。
9. **绿牌与草丛粘成宽条**：专用字符窗口搜索收紧到车牌子区域。
10. **裁剪切边字符**：矫正外扩系数提高到 12%（等比放大不改长宽比），找回边缘字符。

### 6.2 局限与改进方向

| 局限 | 改进方向 |
|---|---|
| 小幅面+透视+低对比+纹理背景（真实集漏检 2 张） | 神经网络检测（作业说明神经网络测试要求更高） |
| 透视畸变未完整建模 | 四边形透视矫正 |
| 同色草丛粘连绿牌个别末位字符略切 | 更精细的牌面边界分割 |
| 强反光/过曝导致底色偏移 | 放宽颜色范围 / 自适应直方图均衡 |
| 双层牌字符验证按单层设计 | 增加双层牌分支 |
| 裁剪边缘残留少量背景 | 由 B 的二值化/连通域清理 |

是否引入神经网络：按分工方案，先建立可解释传统基线，再根据真实测试中最主要的失败原因决定。
本模块真实集 26/28 的漏检主因是小幅面透视+纹理背景，正是神经网络可改善之处。
